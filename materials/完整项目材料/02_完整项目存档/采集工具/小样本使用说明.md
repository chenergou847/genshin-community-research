```powershell

$studyPath = '.\正式采集_小样本v1_20261018'

```

新研究由`register_small_study.py`登记，只运行一次，已有目录拒绝覆盖。首次访问检查：

```powershell
python -X utf8 run_small.py --study $studyPath probe
python -X utf8 execute_small_discovery.py
```

`probe`仅请求一次首屏，不是正式样本。`execute_small_discovery.py`在一个普通会话内顺序执行主检索、审计A、审计B；全部完成后冻结候选库并生成一次随机视频全排列。主组合每项最多3页，审计A/B每项1页，每页20条；不日期递归、不并发。执行已完成时再次调用不发请求。任何访问校验立即停止，退出码非0不能当作完成。

也可逐阶段执行：

```powershell

```

前三页重复命中按BVID去重；数量和排序变化留在请求快照中，不冒称搜索全量。失败页没有冻结成功记录。旧v1—v6候选不混进新有限框；查阅旧材料发现库外遗漏时记录局限，扩框必须新版本。

## 仅核验随机视频前缀

```powershell
python -X utf8 run_small.py --study $studyPath video-progress
python -X utf8 run_small.py --study $studyPath enrich-next --limit 6
```

查看`small_video_queue.csv`和`small_video_review.csv`。`enrich-next`只读取下一顺序少量候选详情，三个副本轮流取；不会把整库逐一抓详情，也不会替你认定内容合格。

按随机顺序填视频审核表：`decision=include/exclude`，`reason`，`reviewer`，`review_kind=human_final/human_ai_agreement`，`final=yes`。纳入项另需`period_evidence`（具体内容位置）、`aid`、`primary_up`、`published_at`、`content_type`。日期字段为整数秒时间戳。明确日期超界可以由程序记录为`deterministic_date_rule`；其他AI初判不能填写成人工定稿。

同一视频若用于两个副本，内容归属分别判断，公共元数据必须一致。待核项挡住顺序推进，不能因为难判断、访问失败或评论少而跳过；每副本到20条合格视频后无需核完剩余候选。候选耗尽时取全部合格视频，零评论仍保留。

```powershell

python -X utf8 run_small.py --study $studyPath collect
```

## 完整清单和定性补查

入选视频需要完整根/回复，窗口前的根也不跳过。数据在`small_comments.jsonl`、`small_observations.jsonl`及`small_collection.json`；采集失败不换视频。若未完整返回，部分正文仍保留。

在`small_collection_review.csv`逐视频核对终点、总数口径及差额，填`status=accepted`、`final=yes`及证据和核验人，再冻结：

```powershell
python -X utf8 run_small.py --study $studyPath freeze-comments
```

600条是编码预算。采集到的历史/窗口/语境正文可能更多；程序保存它们用于完整性和随机抽取，不把它们全部叫统计样本。

定性补查从已入选且完整枚举的视频选6名不同UP开发、另3名UP验证；每个最多10条随机原始窗口发言。先完成6个开发来源再启动验证，不能复用UP：

```powershell
python -X utf8 run_small.py --study $studyPath qual-queue --mode abyss --bvid 实际BVID --role development
python -X utf8 run_small.py --study $studyPath qual-status
```

在`small_qual_registry.json`填写每项的`new_information=none/problem/condition/counterexample/multiple`、`evidence`、`reviewer`、`review_kind`和`final=yes`。固定来源及ID另有冻结文件，不能删掉不合意的来源重抽。可用UP不足就记录缺口；不宣称达到原主题饱和标准。

填写`codebook.json`中的版本、相关性规则、语境、主题定义/纳排例子、混合表达和人工核定人。需包含`other_current_experience`。`exploration_review.status`如实填`limited`并记录证据与核定人，不用一个completed标记冒充验证。


每个抽中项均处理，不相关和不明不替换。填相关性、理由、语境证据、处理人、`review_kind=human_final/human_ai_agreement`、`final=yes`，相关项再填冻结主题ID（分号分隔）及本人经历主题。未提及问题可以不填主题，不能强行归为负面；不相关/不明项不填主题。

## 盲复核与加权结果

```powershell
python -X utf8 run_small.py --study $studyPath lock-coding
```

每副本最多30条主样本生成独立随机复核顺序；材料文件不含原码。填`small_blind_review_001.csv`：复核相关性和主题、人工处理人、核验方式、日期/角色检查、语境及裁决依据。`review_kind`如实使用`human_ai_agreement/same_person_blind_recode/independent_human_coders`。分歧项须填`resolved_relevance/resolved_themes/resolved_self_experience_themes`；空主题是合法裁决，但相关性不可空。程序分开计算一致率和实际裁决修正率。

锁定后发现需要重审全部编码：更新工作表并带原因重新锁定，保留旧快照、旧复核表和同一随机ID：

```powershell
python -X utf8 run_small.py --study $studyPath lock-coding --revision-reason '具体误码与影响范围'
python -X utf8 run_small.py --study $studyPath estimates --draft
python -X utf8 run_small.py --study $studyPath estimates
```

新复核表依次为002、003等，不覆盖001。复核未完成、一致率低于90%或修正率超过5%时，正式输出拒绝；草稿明确标记DRAFT。这些检查线不是总体误码率保证。

结果分三个副本输出加权比例、视频聚类近似95%区间、是否达到±10pp、不明相关性最坏情形范围与敏感性分析。不能把600条混合计算总占比，也不能把每视频10条直接等权平均。未达精度据实报告，不自动补样。未观察到主题且不是完整普查时，不输出“0误差”。

`status`分别报告候选、已入选来源、入选视频窗口ID数和原始随机样本；目标与实收分开。所有数据仍需人工核定，不以离线测试通过代表真实采集完成。

## 接近视频目标时的首帧取证

`cache_review_first_frames.py --study $studyPath --batch 批次号 --limit 20 --cap-remaining`只为每副本尚差的目标数量准备下一段随机候选首帧。例如19/17/18条合格时，先读下一段1/3/2条；如果某条不合格，下一批沿原顺序继续。该选项只减少额外预读，不能把未知资格当成合格、跳过待核来源或改变随机顺序。调用前需先读取这些候选详情；无此选项时保留原最多20条轮流取证行为。
